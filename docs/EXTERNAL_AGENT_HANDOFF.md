# External Agent Handoff: NGN Generator Architecture & Stability Analysis

## 1. The "Continuous Problem": Data Entropy & Schema Drift

**The Core Issue:**
We are building a high-fidelity NCLEX-NGN Generator. The system is designed to produce "Golden Standard" items that mimic the complex clinical reasoning of the actual exam.
However, we face a recurring cycle of **Entropy**:
1.  **Generation Phase**: We prompt the AI with strict "Golden Templates" (v3/v4).
2.  **Ingestion Phase**: The `UnifiedDataPipeline` normalizes this data. **Drift happens here.** Valid, complex AI outputs (like specific `rationales` logic or `Matrix` row IDs) are sometimes stripped, flattened, or "repaired" into generic placeholders because the validator logic is too aggressive or out of sync with the latest Prompt Standard.
3.  **Rendering Phase**: The `ItemRenderer` fails to find the expected data (e.g., missing Highlight keys), resulting in broken UIs (empty rationales, non-functional logic).

**Recent Specific Failures (From Project History):**
*   **Highlight Items**: Specific `rationales` for `<span>` IDs were being dropped or mis-mapped during ingestion, causing the frontend to show empty feedback despite the AI generating it correctly.
*   **Matrix Items**: Row/Column logic was being flattened during normalization, breaking the scoring validation.
*   **Magic Fix**: The repair service was injecting generic "placeholder" content instead of context-aware clinical data.
*   **Duplicate Items**: Generated items were appearing as duplicates, requiring fixes in the ingestion pipeline ID handling.

## 3. The "Golden Pipeline" (End-to-End Workflow)

Understanding this 11-step flow is critical to debugging.

### Phase 1: Creation (The "Ideal")
1.  **Templates (`docs/external_prompts/Golden Prompts/*.md`)**: The source of truth. Defines the JSON structure.
2.  **Configuration (`src/config/promptTemplates.ts`)**: The functional mirror of the templates used by the code.
3.  **Generation Service (`src/services/questionGenerationService.ts`)**: Constructs the prompt, injects variables (`[FOCUS]`, `[LEVEL]`), and calls Gemini/OpenAI.

### Phase 2: Ingestion & Protection (The "Gatekeeper")
4.  **Raw Input**: The AI returns a JSON string (Draft Item).
5.  **Unified Pipeline (`src/services/UnifiedDataPipeline.ts`)**: The entry point. It calls `transform`.
6.  **Schema Enforcers (`src/schemas/*.ts`)**: Zod schemas check if the item meets the "Golden" standard.
7.  **Auto-Fill Service (`src/services/ingestion/AutoFillService.ts`)**: If schemas fail (e.g., missing `mnemonic`), this service detects the gap and asks the AI to generate *just* that piece.
8.  **Item Managers (`src/services/managers/*.ts`)**: Specialized classes (e.g., `BowTieManager`) apply type-specific logic (e.g., ensuring exactly 2 correct actions).

### Phase 3: Delivery (The "Real")
9.  **Registry (`src/registry/index.ts`)**: Maps the Item Type string to its Renderer and Configuration.
10. **Normalization (`ItemRenderer.tsx -> normalizeConfig`)**: A final safety pass before rendering.
11. **Rendering (`src/components/item-types/renderers/*.tsx`)**: The component (e.g., `CaseStudyRenderer`) displays the item.

## 4. Critical Files Map

### Brain (Logic)
*   `src/services/UnifiedDataPipeline.ts`: **Most Critical.** The central hub for all data transformation.
*   `src/services/questionGenerationService.ts`: Controls the AI prompts.
*   `src/services/ingestion/AutoFillService.ts`: The "AI Surgeon" for repairing items.
*   `src/services/ingestion/ItemIngestionService.ts`: The legacy entry point wrapper.
*   `src/services/geminiService.ts`: Contains the "Magic Fix" logic.

### Heart (Definitions)
*   `src/config/promptTemplates.ts`: The hardcoded string templates. **Must match MD files.**
*   `src/types/master-schema.ts`: The TypeScript interface definitions.
*   `src/schemas/shared.ts`: Defines the shared `Rationale` shape.
*   `src/services/managers/ItemManagerFactory.ts`: Dispatches logic based on Item Type.

### Face (UI)
*   `src/components/item-types/ItemRenderer.tsx`: Main wrapper.
*   `src/components/item-types/renderers/CaseStudyRenderer.tsx`: Complex 6-screen logic.
*   `src/components/item-types/renderers/BowTieRenderer.tsx`: Complex DnD logic.
*   `src/components/RationaleSheet.tsx`: Displays the detailed educational breakdown.
*   `src/components/StudentPreviewModal.tsx`: The main preview container.
*   `src/components/UltimateRationale.tsx`: The visual engine for feedback.

### Limbs (Output)
*   `src/services/exportService.ts`: Handles CSV/PDF/QTI exports.
*   `src/registry/index.ts`: The lookup table linking types to code.
